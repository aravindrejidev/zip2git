How Zip2Git works

Four calls to the GitHub Git Data API, made in order, straight from your browser.

Every file you keep checked in the file tree is uploaded as a blob. Those blobs are assembled into a single tree — merged on top of your branch's current tree, so files you didn't touch are left alone. The tree is wrapped in one commit, and finally the branch reference is moved to point at it — creating the branch first if it doesn't exist yet. Because the commit is only created after every blob exists, and the ref only moves after the commit exists, there's never a moment where the repository sits half-updated.

Getting a token

Zip2Git needs a Personal Access Token with repo scope to create commits on your behalf.

Go to github.com/settings/tokens — or from GitHub, open Settings → Developer settings → Personal access tokens → Tokens (classic).
Click "Generate new token" → "Generate new token (classic)". Give it a name like zip2git and pick an expiration you're comfortable with.
Check the top-level repo box ("Full control of private repositories"). That single checkbox covers everything Zip2Git needs — reading and writing blobs, trees, commits and refs.
Scroll down and click "Generate token." GitHub shows the value exactly once — copy it now, since reopening the page later won't reveal it again.
Drop it into the token field in Step 1 of the Workspace. Check "remember token" only on a device you trust, since it's saved to that browser's local storage.
