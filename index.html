Blobs, tree, commit and ref update — one atomic call sequence, straight from your browser to the GitHub API

Built for whole projects, not loose files

Three things Zip2Git is deliberately strict about, because a partial upload is worse than no upload.

Exact mirroring

Nothing is auto-excluded. .github/workflows, .gitignore, dotfiles and build configs all land in the commit exactly as they were in your ZIP or folder.

Atomic API engine

Every file becomes a blob, the blobs become one tree, the tree becomes one commit. Hundreds of files land in a single call sequence — never a pile of one-file commits.

Client-side privacy

Your token and your files are read directly into browser memory and sent straight to api.github.com. There's no Zip2Git server in between to store or see either one.

Getting a token

Zip2Git needs a Personal Access Token with repo scope to create commits on your behalf.

Go to github.com/settings/tokens — or from GitHub, open Settings → Developer settings → Personal access tokens → Tokens (classic).
Click "Generate new token" → "Generate new token (classic)". Give it a name like zip2git and pick an expiration you're comfortable with.
Check the top-level repo box ("Full control of private repositories"). That single checkbox covers everything Zip2Git needs — reading and writing blobs, trees, commits and refs.
Scroll down and click "Generate token." GitHub shows the value exactly once — copy it now, since reopening the page later won't reveal it again.
Drop it into the token field in Step 1 above. Check "remember token" only on a device you trust, since it's saved to that browser's local storage.
